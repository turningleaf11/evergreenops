How this stays useful

Three rules, each one aimed at a specific way maps normally rot.

  • It holds structure, not status Process, owners, and routing change monthly. Task status changes daily. The Miro Task Board keeps the fast-moving things; this map keeps the slow ones, so it isn't stale a week after it's written.
  • Every node says whether it's real Automated, manual, or unmapped — stated on the node itself. A step drawn as a box doesn't get to imply it runs. Steps that exist but aren't documented are drawn as dashed outlines so the hole is visible.
  • Gaps live next to the process What's missing at a stage is written into that stage, not filed in a separate improvements doc. It's how bottlenecks stay in view instead of being rediscovered.
