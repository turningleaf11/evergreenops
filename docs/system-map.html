The underwriting path

Most deals should die in the first sixty seconds. At 30–50 underwrites a week, the screen is the only thing protecting the underwriters' time — so it runs before any tool is opened.

Two distinct filters, often confused. The buy box is the filter, applied before underwriting. The tools' own thresholds — DSCR 1.25, CoC 7%, IRR 12% — are the verdict, applied after.

Why exceptions have types

A widened_band exception simply relaxes a threshold: note it and carry on. A conditional_adjustment is curable, not waivable — a 2-bed that could take a third bedroom is still a 2-bed until someone confirms the conversion is feasible. Cash prices the cure and flags it. Cash never decides it.

Handoffs

Every arrow above where work changes hands. These are the joints where things get dropped.

Albus → Cash

A row in agent_tasks assigned to cash. Albus sets it to doing; Cash returns it at review with findings in result.

Cash → underwriting tool

Cash prepares inputs and reads results. It never does the arithmetic itself — the tools already do that well, and a second implementation would just disagree with the first.

Tool → underwriting_runs

The cross-app index. Which tool, which record, a deep link back, the verdict and headline metrics. Without it there is no single place to ask "what have we underwritten?"

Cash → underwriter

Status ceiling is review. A human signs off on every number that leaves the building. Cash drafts offers and LOIs; Cash never sends one.

Dex → Codex

Dex spawns a Codex subagent with the full brief — Codex sees none of the surrounding conversation, so the brief carries repo, stack, conventions, and deliverables.

approved → GitHub Actions

Flipping a task to approved fires trigger-github-task, which builds against the repo and opens a PR. No agent may set this. It has never once been fired by anything but a human clicking the dropdown.

Known gaps

Written down so they stay visible. A gap nobody has named is the one that bites.

  • OpenClaw skills are not on a persisted volume They live in the container's writable layer. docker restart preserves them, but any image rebuild or compose up discards them — silently reverting the fleet to whatever shipped in the image, with no error raised. Canonical copies in docs/agents/ make it recoverable, but only if someone notices.
  • Memory has no approval gate Any agent can write to memories directly. A wrong underwriting lesson compounds quietly across every future session that reads it.
  • Napkin write-path is built but not installed Until the two MCP tools are dropped into the repo, prefilling a multifamily model from an extracted T12 remains manual — the single largest time sink in that workflow.
  • Calibration has never run underwriting_runs.actual_* is the point of the table — comparing what was projected against what a deal really did. It stays theoretical until enough deals close.
  • Co-living / PadSplit is undefined An exit strategy the team hasn't modeled yet, so it is deliberately absent from the buy box rather than guessed at.
  • Lease options are on hold No model, by decision rather than oversight.
